# 农间诊运营文案版本说明

## 版本信息

- 版本号：`1.0.0-mvp-ops`
- 配置文件：`data/agriculture/operations.v1.json`
- 发布状态：草稿，待农艺专家确认、待产品负责人批准
- 覆盖作物：番茄、黄瓜、水稻、玉米、柑橘
- 适用范围：图片质量提示、风险等级、下一步行动、安全边界、专家复核
- 变更日期：`2026-09-29`

## 本版目标

本版把首批运营内容从问题知识条目中拆出来，形成可以独立审核、版本化和回滚的文案配置。每条内容都有稳定 `code`，并绑定适用作物和适用场景，后续后台或知识服务可以按 code 管理，不需要修改页面逻辑。

## 文案原则

1. 先说现在做什么，再解释可能原因。
2. 使用“疑似、可能、较符合、需要补拍确认、建议专家复核”，不把图片结果写成确诊。
3. 每条行动尽量包含明确时间，如“今天完成”“24 小时后复查”“3 天后检查”。
4. 高风险和严重风险必须包含人工复核路径。
5. 不编造农药商品、有效成分、剂量、次数、混配方法和固定安全间隔期。
6. 涉及药剂时只提示核对当前有效登记和产品标签；涉及人畜不适时转医疗或应急渠道。
7. 使用普通农户可以理解的词，专业词只在必要时出现，并配合动作解释。

## 主要文案变化

### 风险等级

- 从单纯颜色提示改为“等级名称 + 影响解释 + 时间动作 + 是否复核”。
- 高风险从“注意”改为“当天控制传播、24 小时补拍、提交农技员复核”。
- 严重风险增加当地植保或农技部门路径，避免用户把 AI 结果当作最终结论。

### 图片质量

- “图片不合格”改为具体原因，例如“画面偏暗”“病斑边缘不清楚”“异常部位太小”。
- 每条提示都带下一步动作，避免用户停在失败状态。
- `IMAGE_WRONG_PART` 用于提示叶片正反面、茎基部、果实等关键证据缺失。

### 下一步行动

- 行动统一拆为“现在做、观察、暂时不要做、请专家复核”。
- 增加同角度复查照片要求，便于比较病斑范围和新叶变化。
- 对缺素和生理性问题统一增加根区、肥水记录和检测边界，避免诱导大量补肥。

### 安全边界

- 统一保留“辅助判断”免责声明。
- 明确禁止固定剂量、统一安全间隔天数、未经核验的药剂和规避监管内容。
- 增加人员或牲畜接触农药后不适的安全事件转人工文案。

## 审批和发布流程

1. 内容负责人根据 `data/agriculture/operations.v1.json` 完成逐条自检。
2. 农艺专家确认作物适用性、动作可执行性、时间条件和用药安全边界。
3. 产品负责人确认页面展示顺序、按钮文案、适用场景和版本范围。
4. 两方都确认后，将 `approval` 字段更新为实际人员、时间和审批记录。
5. 生成配置校验值，复制到测试环境并保留上一版本作为回滚版本。

## 不属于本版本的内容

- 任何具体农药商品名、有效成分、固定剂量、混配方案和统一安全间隔天数。
- 任何“保证治愈”“百分之百确诊”等承诺。
- 任何未经授权的真实农户案例图片和未完成许可核验的图片。
- 页面程序逻辑、接口逻辑和 AI 模型规则实现。

## 下个版本建议

- 收集每种作物至少 10 个本地田间真实案例，并分别标注正例、易混淆负例和健康对照。
- 让农艺专家补充不同地区、露地和棚室场景的时间条件。
- 对老人用户进行 5 人可用性测试，记录不理解的术语和按钮。
- 根据“补拍成功率、专家推翻率、复查完成率”调整文案，不直接根据点击率降低安全提示。
