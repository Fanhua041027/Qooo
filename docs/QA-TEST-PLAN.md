# 农间诊 MVP QA 测试计划

文档版本：`0.1.0`  
适用版本：`0.1.0-mvp`  
测试对象：微信小程序、MVP API、Mock AI 适配器  
最后更新：2026-09-28

## 1. 测试目标

本轮测试只验证一条核心闭环：

```text
登录/进入首页
  → 拍照或从相册选择作物图片
  → 获得图片质量反馈
  → 提交诊断并看到处理状态
  → 查看辅助判断、风险等级和行动建议
  → 把建议创建为农事任务
  → 在诊断历史和任务列表中再次查看
```

测试结论分为：

- `通过`：满足预期，无阻断问题。
- `有条件通过`：存在已知限制，但不影响演示闭环，且已在发布说明中明确。
- `不通过`：存在 P0/P1 缺陷或核心闭环无法稳定完成。

## 2. 测试范围

### 2.1 本轮覆盖

- 模拟登录、登录态保留和退出。
- 首页主入口、最近诊断和待办摘要。
- 相机/相册授权、选择、预览、删除、重新选择和提交。
- 图片尺寸、模糊、过暗、主体不清等质量提示。
- 诊断创建、处理中、成功、失败、补拍和重试。
- 风险等级、置信度、判断依据、行动建议和安全说明。
- 从诊断建议创建农事任务、任务完成和逾期展示。
- 诊断历史、空状态、错误状态和弱网恢复。
- iOS、Android、微信开发者工具及不同屏幕尺寸适配。
- API 响应格式、请求追踪 ID 和重复提交保护。

### 2.2 本轮不覆盖

- 真实微信支付、商城、社区、物联网和视频问诊。
- 真实专家在线会诊。
- AI 医学级或农学级准确率认证。
- 大规模并发、灾备切换和跨地域部署。
- 真实农药处方有效性。本版本的 AI 输出只能作为产品演示和辅助判断。

## 3. 测试环境

| 环境 | 用途 | 最低要求 |
| --- | --- | --- |
| 微信开发者工具 | 页面、路由、Mock 和基础交互检查 | 当前稳定版；基础库 `3.0.0+` |
| iPhone 真机 | iOS 授权、相机、安全区、触摸与字体检查 | iOS 16+；当前微信稳定版 |
| Android 真机 | Android 授权、返回键、弱网和低性能检查 | Android 10+；当前微信稳定版 |
| MVP API | 前后端联调 | Node.js 20+；`GET /api/health` 返回成功 |
| Mock 模式 | 可复现异常状态 | 能固定触发成功、处理中、低置信度、图片不合格和失败 |

测试数据优先使用 [TEST-ACCOUNTS.md](./TEST-ACCOUNTS.md) 中的账号和无个人隐私的图片。每轮回归前重置测试账号数据，记录前端版本、后端版本、基础库版本和设备信息。

## 4. 缺陷等级和发布门槛

| 等级 | 定义 | 示例 | 发布要求 |
| --- | --- | --- | --- |
| P0 | 核心闭环不可用、数据越权、严重误导或应用崩溃 | 无法提交诊断；高风险结果未显示安全说明；用户看到他人数据 | 必须清零 |
| P1 | 核心功能明显受损，但存在临时绕行方式 | 上传失败后只能重新进入；任务创建后丢失；主要真机布局遮挡 | 原则上清零；例外需产品和技术负责人共同签字 |
| P2 | 局部体验或非核心功能问题 | 次要文案截断；个别动画抖动 | 可带风险发布，必须登记 |
| P3 | 优化建议 | 轻微间距、非关键性能优化 | 可进入后续版本 |

发布前必须满足：P0 为 0、未豁免 P1 为 0、所有 P2/P3 已登记负责人和目标版本。

## 5. P0 验收标准

以下各项必须全部通过：

1. 首次用户能通过模拟登录进入首页；刷新或重新进入后登录态仍有效，退出后个人数据不再展示。
2. 首页首屏能明确看到“拍照诊断”主入口，从首页进入选图流程最多一次点击。
3. 用户能调用相机和相册；拒绝权限时页面说明原因并提供恢复路径，不出现空白页或死循环授权。
4. 无图片时不能提交；选图后可以预览、删除和重新选择。
5. 图片不合格时显示具体原因与下一步动作；轻微质量问题允许用户确认后继续，严重问题要求重拍。
6. 点击提交后 3 秒内出现明确的上传或分析状态；连续点击不会创建重复诊断。
7. 诊断在合理超时后进入成功或失败状态，不允许无限加载；失败时可重试且保留已选图片或给出明确说明。
8. 成功结果至少显示作物、可能问题、置信度/可信程度、判断依据、低/中/高风险和一条可执行建议。
9. 所有结果显示“辅助判断”说明；高风险或低置信度结果明确建议补拍或人工复核。
10. 没有可靠依据时不得生成具体药剂剂量；涉及用药的内容必须包含适用范围和安全风险提示。
11. 用户能从结果页创建农事任务，默认带入建议标题、关联诊断/地块和建议时间；刷新后任务仍可查看。
12. 诊断历史按时间倒序展示，点击能回到对应详情；不同测试账号之间数据隔离。
13. 断网、超时、服务错误均有可理解提示和重试入口；恢复网络后不需要重启小程序即可继续。
14. iPhone 与主流 Android 真机上没有阻断点击的遮挡，底部安全区正确，文字不依赖颜色单独表达状态。
15. 所有 API 响应具有 `code`、`message`、`requestId`；服务端日志能使用 `requestId` 定位请求。

## 7. 兼容性测试矩阵

| 平台/设备 | 重点 | 必测结果 |
| --- | --- | --- |
| 微信开发者工具当前稳定版 | 路由、Mock、网络面板、控制台错误 | 核心闭环通过；无未处理异常 |
| iPhone SE 或同级小屏 | 首屏信息密度、按钮触达、底部安全区 | 主按钮可见；无横向溢出；底栏不遮挡内容 |
| iPhone 14/15 系列 | 刘海/灵动岛、安全区、相机返回 | 自定义导航和底部操作区显示正确 |
| Android 低端机（4 GB 内存） | 图片压缩、长列表、低性能 | 不崩溃；提交后及时反馈；可接受降级动画 |
| Android 主流机 | 系统返回键、权限、相册 | 返回路径正确；拒绝/恢复权限有效 |
| 微信基础库 `3.0.0` | 项目声明的最低兼容边界 | 不使用更高版本独占 API，或提供降级提示 |
| 系统大字体 | 125%～150% 字号 | 关键信息不截断；按钮仍可点击 |

如果无法获得某类真机，必须在测试报告中标记“未覆盖”，不得写为“通过”。

## 8. 非功能检查

### 8.1 易用性与无障碍

- 风险级别同时使用文字、图标和颜色，不能只依赖颜色。
- 主要点击区域建议不小于 `44px × 44px`。
- 错误提示说明“发生了什么”和“下一步怎么做”。
- 农业术语提供普通用户能理解的说法。
- 加载超过 1 秒显示状态；超过合理阈值提供取消或重试。

### 8.2 数据与安全

- 用户图片、地块和诊断记录按账号隔离。
- 日志不打印令牌、手机号、精确地址或原始个人信息。
- Mock AI 结果明确标注演示/辅助判断。
- 未经可靠规则校验不得显示具体药剂剂量。
- 删除、退出等重要操作有明确反馈，删除操作需要二次确认。

### 8.3 性能基线

- 首页首屏在正常网络下尽快可交互，禁止因次要请求阻塞主入口。
- 选择图片后 1 秒内出现预览或处理中反馈。
- 提交诊断后 3 秒内出现上传/分析状态。
- 轮询采用合理间隔，页面隐藏后停止无意义高频请求。
- 诊断历史达到 100 条时仍能正常滚动和进入详情。

## 9. 回归与冒烟清单

每次合并到可演示分支后执行以下冒烟测试：

1. 启动 API，检查 `/api/health`。
2. 启动小程序并模拟登录。
3. 从首页进入拍照诊断。
4. 先用不合格图片验证质量提示，再换合格图片。
5. 提交诊断并等待结果。
6. 检查风险、依据、建议和免责声明。
7. 从建议创建任务并标记完成。
8. 返回诊断历史重新打开结果。
9. 断网触发一次失败，再恢复网络重试。
10. 检查控制台无未处理异常，记录前后端 `requestId`。
