# QdUI 组件规范

QdUI 采用“基础组件 + 业务组件”两层结构。基础组件不包含农业业务词，业务组件组合基础组件并承载诊断、任务和天气语义。

## 基础组件

| 组件 | 规格 | 必须状态 |
| --- | --- | --- |
| `Button` | 高度 96/80/64rpx；主、次、描边、危险、幽灵五种层级 | 默认、按压、禁用、加载 |
| `Card` | 白色表面，20rpx 圆角；边框与阴影二选一 | 默认、按压、选中、禁用 |
| `Badge` | 紧凑状态信息，不承载操作 | 中性、信息、成功、警告、危险 |
| `Tag` | 可筛选或可移除；最小高度 56rpx | 默认、选中、按压、禁用 |
| `Input` | 可见标签置于输入框上方，不只使用 placeholder | 默认、聚焦、已填、错误、禁用 |
| `Textarea` | 最小 4 行；显示字数和明确标签 | 默认、聚焦、错误、禁用 |
| `ImageUploader` | 拍摄、相册、预览、删除、重拍 | 空、已选、上传、模糊、不合格、失败、权限拒绝 |
| `BottomSheet` | 用于选择和补充操作；顶部有标题，底部尊重安全区 | 关闭、打开、长列表、键盘弹起 |
| `Dialog` | 只用于需要确认或阻断的决策 | 信息、确认、危险、不可恢复 |
| `Toast` | 反馈完成结果，不承载长说明 | 成功、失败、信息；1.8–3 秒 |
| `Skeleton` | 保留真实内容尺寸，避免布局跳动 | 首次加载、局部刷新 |
| `EmptyState` | 说明为什么为空，并提供一个下一步 | 无数据、无结果、无农场、无任务 |
| `ErrorState` | 说明错误、数据是否保留、如何恢复 | 断网、超时、服务失败、权限拒绝 |

## 业务组件

| 组件 | 结构 | 关键约束 |
| --- | --- | --- |
| `RiskLevel` | 图形标记 + 风险文字 + 简短含义 | 不依赖颜色；高风险必须有处理时限 |
| `DiagnosisResult` | 作物、可能问题、可信度、风险、依据、免责声明 | 先行动后详情；低可信度提供补拍或复核 |
| `TaskCard` | 时间、任务、地块、来源、完成按钮 | 完成按钮触控区不少于 88rpx |
| `WeatherCard` | 温度、天气、农业动作建议 | 天气数据与行动建议分层，不显示假精度 |

## 组件组合规则

- 页面只保留一个 `primary Button`；其余动作使用 `secondary`、`outline` 或文本按钮。
- `Dialog` 不作为首选编辑容器；简单编辑使用内联区域，复杂选择使用 `BottomSheet`。
- `Card` 仅用于同一信息单元，禁止卡片嵌套卡片。
- `Toast` 只反馈结果；需要用户决策时使用页面内提示或 `Dialog`。
- 列表加载使用 `Skeleton`，提交操作使用按钮内 loading。
- `RiskLevel`、`ErrorState` 和 `DiagnosisResult` 必须提供屏幕阅读器可读标签。

## 实现状态

仓库已经实现 `qd-button`、`qd-status`、`qd-empty-state` 和 `bottom-nav`。其余组件在 MVP 中可先作为页面内组合模式实现，但视觉 Token、交互状态和文案规则必须遵守本规范，稳定后再提取为独立组件。
