# 农间诊 MVP 缺陷与已知问题

最后更新：2026-09-28  
适用版本：`0.2.0-mvp`

## 使用规则

本文件是 MVP 的缺陷单一登记入口。发现问题后新增一行，并在下方补充复现详情；不得只在群聊中报告。

状态只使用：`待确认`、`已确认`、`修复中`、`待回归`、`已关闭`、`延期`。  
优先级定义参见 [QA-TEST-PLAN.md](./QA-TEST-PLAN.md)。

每条缺陷必须包含：

- 唯一 ID。
- 首次发现版本和环境。
- 前置条件及最短复现步骤。
- 预期结果和实际结果。
- 截图/录屏/日志证据；接口问题附 `requestId`。
- 负责人、目标版本和回归结果。

### BUG-001：正式发布构建门禁未通过（已修复代码问题，待环境回归）

- 环境：Windows 11、Node.js 25.6.1、版本 `0.1.0-mvp`。
- 复现步骤：在项目根目录执行 `npm run typecheck` 与 `npm run build:weapp`；在 `backend` 执行 TypeScript 检查。
- 预期结果：前后端依赖可稳定安装，类型检查和小程序构建均成功。
- 当前结果：根目录 `typecheck`、Taro 构建、后端类型检查和后端单元测试均已通过；真实服务启动仍需要 PostgreSQL、Redis 和对象存储环境。
- 证据：QA 执行记录见 [QA-REPORT-0.1.0.md](./QA-REPORT-0.1.0.md)。
- 发布判断：阻止上传体验版。

### BUG-002：诊断轮询可能无限持续（已修复代码问题，待真机回归）

- 环境：`src/features/diagnosis/useDiagnosisPolling.ts`。
- 复现条件：服务持续返回 `PENDING`/`PROCESSING`，或持续请求失败。
- 预期结果：达到总超时时间或最大轮询次数后停止，显示可理解的失败提示和重试入口。
- 当前结果：每 1200ms 轮询，最多 25 次且总时长不超过 45 秒；超时后停止轮询并提供重新查询和历史入口。
- 发布判断：阻止体验版；满足 P0 验收标准 7 后回归。

### BUG-003：快速双击可能创建重复诊断（已修复代码问题，待真机回归）

- 环境：`src/pages/diagnosis/index.tsx`、`pages/diagnosis/diagnosis.js`。
- 复现步骤：选择合格图片后快速连续点击“提交诊断”。
- 预期结果：整个提交周期复用同一个 `clientRequestId`，且客户端同步锁阻止第二次调用。
- 当前结果：Taro 提交函数增加同步 `submittingRef` 锁，原生页面增加同步 `submitLock`；两套实现都在一次提交周期内复用同一个 `clientRequestId`，服务层和 API Client 均支持按幂等键去重。
- 发布判断：阻止体验版；需用同步锁或预生成幂等键修复并补自动化测试。

### BUG-004：授权拒绝后缺少设置恢复入口（已修复代码问题，待真机回归）

- 环境：`src/pages/diagnosis/index.tsx`、`src/services/media.api.ts`。
- 复现步骤：首次拍照或选图时拒绝权限。
- 预期结果：解释权限用途，并提供调用 `Taro.openSetting` 的明确操作。
- 当前结果：权限错误会显示用途说明和“前往设置”按钮，调用 `Taro.openSetting`；设置 API 失败时显示可理解的重试提示。
- 发布判断：阻止体验版；需在 iOS 和 Android 真机回归拒绝与恢复流程。

### BUG-005：失败诊断无法真正重新分析（已修复代码问题，待回归）

- 环境：`src/pages/diagnosis-result/index.tsx`、`src/mocks/transport.ts`。
- 复现步骤：打开失败诊断，点击“重新分析”。
- 预期结果：调用 `POST /api/v1/diagnoses/{id}/retry`，诊断状态回到处理中并重新轮询。
- 当前结果：Taro 结果页和原生结果页都会调用 `POST /api/v1/diagnoses/{id}/retry`，再进入处理中轮询；Mock Transport 已实现失败或需要补图状态的重试路由。
- 回归证据：`src/mocks/transport.test.ts` 新增失败诊断重试用例。

## 详细记录

### KNOWN-001：服务重启后数据清空（已关闭）

- 环境：MVP API 原型。
- 前置条件：已创建至少一条诊断或农事任务。
- 复现步骤：重启后端进程，再请求诊断历史或任务列表。
- 预期结果：正式版本中数据应持久保存。
- 当前结果：已改为 PostgreSQL/Prisma 持久化，诊断、农场、地块、任务、消息、文件对象和审计记录均有数据库模型与迁移。
- 修复说明：新增 `backend/prisma/schema.prisma`、初始化迁移和 `prisma/seed.ts`；体验环境启动时自动执行迁移与种子数据。
- 回归结果：`npx prisma validate`、`npm run typecheck`、`npm test` 和 `npm run build` 已通过；需在 Docker 可用环境补做真实数据库重启回归。

### KNOWN-002：正式微信登录和生产权限未完成

- 环境：开发/体验环境。
- 复现步骤：使用模拟登录进入应用。
- 预期结果：生产版使用微信 `code` 换取服务端会话，并按用户隔离数据。
- 当前结果：可能使用固定测试用户或开发令牌。
- 临时处理：体验版仅发给内部测试人员；禁止接入真实个人或农场数据。
- 发布判断：内部原型可接受，公开发布前必须修复。

### KNOWN-003：Mock AI 不能作为真实诊断依据

- 环境：所有启用 Mock AI 的环境。
- 复现步骤：提交任意支持的演示图片。
- 预期结果：真实生产模型应经过数据集评测、农业专家审核和安全规则校验。
- 当前结果：结果用于验证接口结构、页面状态和行动闭环。
- 临时处理：结果页必须持续显示“辅助判断/演示数据”说明；不提供未经校验的具体用药剂量。
- 发布判断：缺少声明时按 P0；声明完整时仅限内部原型。

### KNOWN-004：临时图片路径不保证长期有效

- 环境：使用本地 Mock 或微信临时文件路径时。
- 复现步骤：提交图片后清理缓存、换设备或等待临时文件失效，再打开历史详情。
- 预期结果：历史详情可通过受控对象存储地址访问缩略图。
- 当前结果：Real API 模式已通过预签名 URL 完成上传并确认对象；Mock 模式和历史记录中的旧临时路径仍可能失效。
- 临时处理：历史页提供图片加载失败占位，不影响结构化诊断结果查看；后续需要补充受控访问 URL 的历史缩略图展示。

### KNOWN-005：微信订阅消息未接入

- 环境：体验版。
- 复现步骤：提交诊断后离开小程序，或创建临近到期任务。
- 预期结果：取得用户授权后发送订阅消息。
- 当前结果：用户需要回到应用查看状态。
- 临时处理：演示期间保留页面内状态和任务列表，不宣称已发送微信通知。

### KNOWN-006：最低基础库兼容性待确认

- 环境：声明使用 `skyline` 和 `glass-easel` 的构建。
- 测试要求：至少选择一台符合最低基础库边界的 Android 真机执行登录、选图、诊断、建任务完整流程。
- 通过条件：无白屏、组件缺失、点击失效和不可恢复的渲染错误。
- 失败处理：记录设备与基础库版本；必要时提高最低版本或提供渲染降级。

### KNOWN-007：上传与轮询的弱网恢复待回归

- 环境：iOS 与 Android 真机。
- 测试要求：分别在上传中和分析轮询中断网、切后台，再恢复网络。
- 通过条件：不会生成重复诊断；不会无限加载；能够继续、重试或清楚告知最终状态。

### KNOWN-008：大字体布局待回归

- 环境：系统字体 125% 和 150%。
- 测试要求：检查首页、上传页、结果页、任务表单和错误弹层。
- 通过条件：风险、主要建议、主按钮和免责声明可读，按钮不重叠，页面可滚动到全部内容。

- `BUG-010`：结果页历史入口改用 `navigateTo`，避免把非 Tab 页面传给 `switchTab`；自动化构建通过，待微信开发者工具验证真实跳转栈。
